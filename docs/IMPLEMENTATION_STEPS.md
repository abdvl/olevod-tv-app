# 小步实施清单

每一步完成后：验证 → 更新 `PROGRESS.md` → 单独 commit。中断后先读进度，再看 git status，不能重做已完成任务。步骤可因证据拆得更小，不把未验证项标记完成。

| ID | 独立提交范围 | 完成证据 |
| --- | --- | --- |
| S01 | 忽略凭据/构建输出、细化任务、恢复进度规范 | git ignore 与文档检查 |
| S02 | Android 工程、固定工具链、TV launcher、基础主题 | assembleDebug |
| S03 | 奇异果风格原生首页/浏览/搜索/播放界面预览 | 编译 + 模拟器截图；明确预览数据 |

用户要求先提供可批注界面，因此 S03 提前用明确标注的预览数据实现真实 Compose 页面；API/登录风险仍在后续步骤中保留，不能把视觉预览当产品完成。

## 每次提交的记录格式

`步骤 / 做了什么 / 实际执行验证 / 已知限制 / 下一步`。提交历史用 commit subject 关联步骤，避免把当前提交 hash 递归写入本次内容。
凭据从用户本地 `.secrects` 读取，只在必要登录测试中使用，不输出值、不打包、不提交。仅记录格式和测试是否成功。
独立验证 agent 不修改主实现；报告位于 `docs/verification/`，主 agent 修复后重新请求验证。
