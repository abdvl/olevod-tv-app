## 测试方式与结果

新增 [V2HistoryUiTest.kt](../../../app/src/androidTest/java/com/olevod/tv/V2HistoryUiTest.kt)。本机路线使用实际 `HistoryScreen`、HistoryGrid、HistoryRecordCard、TvConfirmDialog 和 Header；注入五条可变 `fixtureRecords` 与只修改该内存列表的 `fixtureDelete`。AppViewModel 使用独立命名空间的 V2FixtureViewModel；fixture 分支不会补全网络元数据。

云样式直接使用 `HistoryGrid(metadata=null, remove=null)`，传入三条记录，包含真实为正的测试 updatedAt 与未知 duration，确保日期隐藏来自只读展示规则，而不是因为日期值恰好为零。该用例没有伪造登录会话或调用 CloudHistoryPanel 的服务端分页。

所有待测导航与弹窗操作使用遥控器按键；没有点击或直接请求某个删除按钮焦点跳过流程。

| 用例 | 结果 | 已证明行为 |
| --- | --- | --- |
| `resumeDeleteRolesNavigateAcrossRowsAndClampTheShortLastRow` | 通过 | 首项 main→delete→次项main→delete 的左右路线；保持 delete 角色向下至第4项、短末行第5项；底部Down不失焦；左回续播，确认打开第5项并准确保留集数/毫秒；逐行上回来源tab及Header。 |
| `cancelReturnsToDeleteAndConfirmationRemovesOnlyTargetThenFocusesNeighbor` | 通过 | 在末行第5条delete打开确认框，默认取消；Back取消后仍是原delete；再次确认仅删除第5条，恢复第4条resume，其他四条保留。 |
| `clearCancelPreservesDataAndConfirmReturnsToValidEmptyState` | 通过 | 从来源tab导航到清空；取消后回清空按钮且五条数据不变；确认只调用一次 null 全清动作，回此设备tab，显示空态且清空按钮消失；Down可达开始浏览并触发一次。 |
| `deletingTheOnlyRecordReturnsToTheDeviceSource` | 通过 | 唯一条目确认删除后无失效目标，回此设备tab并显示空态。 |
