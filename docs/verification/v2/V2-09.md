## 账号 UI 六项

独立新增 [V2AccountUiTest.kt](../../../app/src/androidTest/java/com/olevod/tv/V2AccountUiTest.kt)，直接组合实际 AccountScreen 和确认弹窗，注入 AccountFixture。用户名/密码均为固定的 fixture 字符串；验证码图是嵌入的单像素 PNG，challenge/login 是本地 suspend 回调和可控 Deferred。AppViewModel 使用 V2FixtureViewModel 命名空间隔离，不访问实际账户存储。

| 用例 | 结果 | 已证明行为 |
| --- | --- | --- |
| `firstVisitFocusesUsernameAndEmptyFormCannotSubmit` | 通过 | 无记住信息时默认用户名，Down到密码、Right到数字1；空账号/密码时登录禁用且无提交。 |
| `rememberedAccountStartsAtOneAndKeypadKeepsFiveDigitsUntilExplicitSubmit` | 通过 | 已记住信息默认数字1；按键遍历3列×4行全部键位；方向不输入；四位验证码不自动提交，第五位仍保留；只有移动到登录并确认才一次性提交正确账号、五位验证码与challenge-1。 |
| `busySubmissionIgnoresRepeatedConfirmAndCaptchaRefresh` | 通过 | 延迟登录期间连按确认只产生一次提交；移动到换一张再确认不会启动新challenge，也不清原输入；完成只回调一次成功。 |
| `failedLoginClearsDigitsRefreshesPairAndReturnsToOne` | 通过 | 第一次失败后清验证码、请求新pair并回数字1；第二次提交使用新的challenge-2及新输入，没有复用旧ID。 |
| `refreshingClearsDigitsButCompletionDoesNotStealNewFocus` | 通过 | 换一张清空输入，等待时留在刷新；用户再移动到数字2，刷新完成仍保持数字2。 |
| `forgettingRememberedCredentialsCanCancelBackToItsTrigger` | 通过 | 清已保存信息默认取消，Back回原触发按钮并保留显示；再次确认后本地表单清空并回用户名。fixture模式不调用真实vault清除。 |

UI 测试通过实际遥控器方向/确定/返回及数字键，不用直接点击或 requestFocus 跳过待测路线。图像样本只避免网络请求；本轮不凭该单像素图声称真实验证码对比度或识别可用性已经验收。

## 状态测试独立审阅与执行

主执行 agent 新增 [V2AccountStateTest.kt](../../../app/src/androidTest/java/com/olevod/tv/V2AccountStateTest.kt)，独立验证 agent 只读审阅后在本次限定运行中执行，4/4 通过。这四例包含实质性状态/存储断言，不是仅构造对象或重复实现表达式。

| 用例 | 实际断言与边界 |
| --- | --- |
| `rememberedStateWaitsForSuccessfulDiskWrite` | 用 CountDownLatch 阻塞注入 vault 的 save；写入未完成时 AppViewModel.rememberedCredentials 必须为 null，释放后才出现指定用户名。证明发布顺序，但 vault 是模拟存储，不是 Android Keystore 的真实落盘测试。 |
| `failedPersistenceAllowsLoginAttemptAndNeverClaimsRemembered` | 注入 save 抛 IOException；saveLoginCredentials 正常返回，rememberedCredentials 仍 null，错误文案准确。证明保存预处理失败不会阻断后续流程；没有实际执行 login API，也未调用该 vault 中声明的失败 clear。 |
| `favoriteIntentIsExactAccountAndConsumedOnlyOnce` | 错误 movieId不消费；正确ID返回期望true一次，第二次为空；不同账号意图返回空且被清除。证明内存消费规则，不是服务器收藏请求次数验收。 |
| `explicitScopeDeletionCannotDeleteAnotherAccount` | 在隔离 SQLite 中为同vodId写入 account-a/account-b/guest 三条；显式删除a后，guest视图保留10000ms，原始表仍有b的70000ms及共两行。确实调用生产HistoryStore删除并检查另一scope，而不是仅检查传参。 |

这补充了 V2-08 中未执行真实数据库删除的范围，但仍没有覆盖删除时的真实登录切换和云端服务。

## 搜索首轮失败与修正

## 登录来源与收藏意图只读复核

- 根 `loginOrigin` / `loginFavorite` 保存本次来源和期望收藏状态；Back取消或Header改页清除此登录意图。成功后才创建带movieId/desired/account的PendingFavorite，回原screen。
- NativePlayer 使用 `consumeFavoriteIntent`，仅在账号匹配、desired与当前状态不同才调用设置操作，避免将明确期望误写成再次toggle。
- 先前指出的意图遗留已修：NativePlayer离开时撤销该片未消费意图，AppViewModel清账号缓存时也撤销。此项源码复核已关闭；真实“详情失败后离开再回来”路线尚未执行。
- 登录成功响应后，存储提交与对应内存账号迁移包在NonCancellable段；进入及退出该段检查调用方取消，避免取消页面随后重放来源动作。当前状态测试没有模拟实际会话磁盘提交中途取消。
- 收藏请求发出前使缓存失效，处理“服务端可能已变更、响应被取消”的不确定结果；未进行真实服务端复核。

这些根路由/实际媒体代码的只读结论与AccountFixture UI证据分开，不扩展为真实登录、VIP、云历史及收藏的完整端到端验收。
